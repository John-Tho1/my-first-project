# 제품 명세와 사용 흐름
상태: 제안된 구현 요구사항. 성과 수치·사용성은 아직 검증하지 않음.

## 1. 수집 부담을 줄이는 설계
필수 입력은 원문 하나뿐이다. 제목·연재·독자·근거·다음 행동은 저장 후 AI가 제안한다. 자동 분류는 확정값을 덮어쓰지 않는다. 원문과 제안은 구분한다.
- 텍스트: 복사/붙여넣기와 자동 임시 저장. 저장 성공 여부를 명확히 표시.
- URL: URL과 사용자의 “왜 저장했는지”를 먼저 저장. 원문 추출 실패여도 URL/메모는 유지.
- 음성: M2에서 파일 업로드→비동기 전사→사용자 수정. 브라우저 녹음은 기기 확인 후 추가. 원음 보존 선택.
- 파일: 허용 형식·크기 제한. 업로드 진행/중단/재시도. 확장자뿐 아니라 MIME·파일 내용 확인.
- 모바일: 반응형 페이지·홈화면 설치를 우선. OS 공유 메뉴 수신은 브라우저 지원을 확인한 뒤 추가하며 URL 붙여넣기를 항상 제공.
- 오프라인: 기본은 온라인 앱. “이 기기에만 임시 저장” 여부를 구분하고 서버 저장으로 오인시키지 않는다. 오프라인 예약 게시 불가. 로그아웃 시 로컬 초안 처리 안내.

빠른 저장 목표 [실험 가정]: 필드 입력 없이 30초 안에 한 건 저장. 기기·망 조건을 기록해 사용자 테스트한다.

## 2. 자동으로 아이디어를 얻는 세 경로
A. 내 소재 재발견: 보관한 메모·미완성 글·독자가 한 질문을 우선. 장기 미사용 소재를 다시 추천.
B. 질문 인터뷰: “어떤 상황이었나 → 무엇을 판단했나 → 독자에게 남길 한 가지는?” 최대 3개씩 질문. 답변을 가상 경험으로 보충하지 않음.
C. 지정한 공개 소스: M5에서 승인한 RSS/공식 블로그/선택 URL만 수집. 조회 범위·주기·수집 ON/OFF를 설정. 검색 제공자와 요금·원문 사용권은 별도 확인. 회사 메일·채팅·전체 Drive 자동 수집은 제외.

추천 카드에 왜 이 독자에게 유용한지, 원문 근거, 이미 쓴 글과 겹치는 지점, 더 확인할 질문을 표시한다. 사실 검증 전에는 “검증된 아이디어”로 표시하지 않는다. 저장량을 늘리기보다 이번에 쓸 소재 1개를 고르는 데 집중한다.
중복: 정규화 URL·파일 checksum은 정확 중복 제안, 주제 유사성은 병합 후보만. 출처·날짜가 다른 관찰은 자동 삭제하지 않음.

## 3. 핵심 화면
| 화면 | 기본 표시 | 주요 행동 |
| --- | --- | --- |
| 오늘 | 이어 쓸 초안 1개·추천 소재 2개·확인 필요 항목·최근 배포 | 빠른 수집 / 10분 작성 / 배포 확인 |
| 소재함 | 원문·수집일·연재·출처·공개 가능성 | 선택·보류·질문으로 발전 |
| 작성실 | 원문/근거 옆 편집기·버전·AI 제안 diff | 개요 생성·부분 수정·사용자 확인 |
| 콘텐츠 카드 | Idea / Audience / Evidence / Risk / Next Decision | 후보→작성→검토 이동 |
| 아카이브 | 태그·연재·독자 문제·확인일·원본/파생 관계 | 검색·재사용·내보내기 |
| 배포함 | 채널·계정명·본문/미디어 미리보기·시간·공개 범위 | 선택 승인·지금 실행·예약·취소·문제 해결 |
| 설정 | 필명·문체·연결 상태·비용·백업·시간대 | 계정 연결/해제·상한·수집 설정 |

UI 문구는 “근거 확인 필요”, “영상 파일 추가”, “계정 다시 연결”, “등록 여부 확인 필요”처럼 사용자 행동을 안내한다. 로그/토큰/DB 상태는 관리 상세 화면에서만.

## 4. 작성 보조와 정체성
Brand Profile: 가칭, 독자, 전문분야, 연재 3축, 존댓말/평어 선택, 피하고 싶은 표현, CTA 원칙, 실제 작성 예문(사용자 제공)으로 구성한다. 고용주 문서·다른 프로젝트 메모리를 자동으로 가져오지 않는다.
AI의 역할:
- 메모의 의미를 보존한 정리와 빠진 질문 제안
- 공개자료 주장과 개인 의견 분리, 확인되지 않은 사실 표시
- 제목/개요/짧은 글/블로그/캐러셀 문안/쇼츠 대본/YouTube 설명 후보
- 1인칭 경험은 user_confirmed=true 근거가 있을 때만. 문체 예문에 있는 사건을 새 글 사실로 이식하지 않음.
사용자는 자동 제안과 자기 문장을 구분해 수정/취소할 수 있어야 한다. 생성 전 원문을 바꾸지 않으며 실패해도 에디터를 비우지 않는다.
외부 AI 호출이 준비되지 않으면 모의 응답과 “프롬프트 내보내기→결과 붙여넣기”를 제공한다. Claude Code/Codex 개발 로그인과 앱의 LLM API 키·요금은 별개.

## 5. 채널별 변환
하나의 core content에서 독립 draft variant를 만든다. Threads 짧은 글, Instagram 카드별 텍스트+완성 이미지, YouTube 대본/제목/설명+완성 영상, Blog Markdown.
채널 제약·말투·CTA·링크·미디어 유무를 각각 확인한다. 원글 수정 후 파생본에는 stale 표시. AI가 승인된 파생본을 자동으로 다시 생성하지 않는다.
영상 대본이 있는 상태와 완성 영상이 있는 상태를 별도로 표시한다. 영상 합성·보이스 클로닝·자동 편집은 초기 범위 밖이다.

## 6. 아카이브와 소유
콘텐츠/버전/출처/실험 가정/발행 참조를 한 덩어리로 export할 수 있어야 한다. Markdown+JSON+첨부파일+checksum manifest. 검색을 위해 외부 벡터 서비스가 필수여서는 안 된다.
글의 조회수와 유료 가능성을 혼동하지 않는다. 향후 수익 아이디어는 실제 독자 질문·반복 요청에 연결하는 hypothesis 카드로만 기록한다. 초기 결제 기능 없음.
나중에 공개 사이트를 만들 경우, private 앱 DB를 그대로 노출하지 않고 승인된 public projection만 별도 발행한다.

## 7. 초기 사용성 평가 [실험 가정]
한 주 동안 사용자 혼자 기록: 저장한 메모 수, 다시 연 메모 수, 초안으로 전환한 수, 한 편의 실제 작성시간, 발행 준비에 걸린 시간. 합격 목표는 사용 시작 후 사용자와 조정.
가상 소재 10개로 기능 검증하되, 사용자 고유 경험과 AI 문체 품질 평가는 사용자가 직접 한다.
