## Task A: LIVE-P2 — daily live-publish cap + instant pause switch
1. Config `PUBLISH_LIVE_DAILY_MAX` (optional, int 1..50, same parsing style as PUBLISH_LIVE_MAX_POSTS in packages/domain/src/config.ts; label in config label map; .env.example + deploy/content-studio.env.example + deploy/scripts/check-env.sh if it validates PUBLISH_LIVE_*). Unset = no daily cap (back-compat); set = enforced.
2. Enforcement in packages/db/src/jobs.ts beginSend, LIVE branch, right after the approval-ref cap: take advisory xact lock `cs_live_publish_daily:${ownerId}` (document lock order: … → ref lock → daily lock; only acquired there). Count DISTINCT other jobs of this owner with a send_intent whose sanitized_details has live_approval_ref (any ref) and created_at > now − 24h, excluding this job; if this job already has a counted live intent it is not new. If count >= max → settle 'blocked' {reason:'live_publish_daily_limit', not_sent:true, used, limit, available_at} lastErrorCode 'live_publish_daily_limit'. available_at = oldest counted intent created_at + 24h. Domain error/label in packages/domain/src/live-publish.ts in Korean: "최근 24시간 실제 게시 상한({limit}건)을 다 써서 게시하지 않았습니다. {시각(모스크바)} 이후 '재시도'로 다시 보낼 수 있습니다." Retry path must work after the window frees (existing retry rules).
3. Pause switch: migration 0046 table `live_publish_controls` (owner_id PK FK, paused boolean not null, changed_at timestamptz, changed_by text) — no row = not paused. Drizzle schema + snapshot via the repo's normal migration generation. DB functions getLivePublishPaused / setLivePublishPaused (audit event 'live_publish_paused'/'live_publish_resumed', sanitized). Route POST /api/live-publish/pause and /resume (owner session + same CSRF/origin checks as other mutating routes). Check: (a) in beginSend LIVE branch inside the same transaction (read row FOR SHARE or under the daily lock) → blocked {reason:'live_publish_paused', not_sent:true}, lastErrorCode 'live_publish_paused'; (b) displayed readiness (assertExecutionAllowed callers / distribution capability display) shows "일시 중지됨". MOCK sends unaffected. Pausing never cancels jobs already past the publish_attempt marker (outcome rules unchanged).
4. UI: settings page section "실제 게시" — status line (켜짐/일시 중지됨/꺼짐(PUBLISH_MODE)), "최근 24시간 n/limit", button 일시 중지 (no confirm) / 재개 (confirm text). Home and distribute/[id] show one visible line "실제 게시: 최근 24시간 n/3" or "실제 게시 일시 중지됨" when a live account exists. Keep ui-safety invariants; add tokens to ui-safety test if new safety text.
5. Tests: unit (config parsing, label), integration (cap blocks 4th distinct job within 24h, retry of same job not double-counted, window frees after 24h with injected clock, pause blocks live but not mock, resume, concurrency: two jobs racing at limit−1 → only one sends under PGlite ordering injection as existing cap tests do, route auth). Do not weaken any existing assertion.

## Task B: EXPIRY-1 — expiry warnings + dev cert renewal
1. Pure function apps/web/lib (or packages/domain) `expiryNotices({accounts, devCert, now})` → list of {kind, level:'warn'|'expired', text, href}. Threads (live) credential expiresAt within 14 days → "Threads 연결이 {MSK 날짜}에 만료됩니다 — 설정에서 다시 연결하세요"; expired → "Threads 연결이 만료되었습니다 — 다시 연결 전에는 실제 게시가 되지 않습니다". Mock accounts ignored.
2. Dev cert: server-only helper reads cert at `DEV_TLS_CERT_PATH` env or default `data/dev-certs/localhost-cert.pem` only when NODE_ENV !== 'production', using node:crypto X509Certificate.validTo; missing/unreadable → no notice (never throw). Within 14 days → "로컬 인증서가 {날짜}에 만료됩니다 — scripts/dev-cert.sh renew"; never print key paths contents.
3. Show notices at top of home page and in settings (accounts section shows per-account expiry warning next to 만료 column). Reconnect = existing connect flow link (no new token refresh API call — out of D31 scope).
4. `scripts/dev-cert.sh` (bash, Git Bash compatible): `check` prints notAfter + days left; `renew [days=90]` backs up existing pem files to data/dev-certs/backup-YYYYMMDD-HHMMSS/, generates new EC P-256 key + self-signed cert CN=localhost SAN DNS:localhost,IP:127.0.0.1 with openssl, never prints the key, tells user to restart dev server and accept browser warning again. Do NOT run `renew` (orchestrator/user does). Bash test with fake openssl optional; at least a unit test for the notice function and the cert reader with a generated test cert fixture (generate in test via openssl if available else skip — or commit a throwaway test-only cert under tests/fixtures, clearly named, not used by the server).
