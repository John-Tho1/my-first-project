## Codex 질문에 대한 답

1. **T13-1 — state 소비 순서:** 소유자·세션을 확인한 뒤 소비하는 방식이 타당하다. 올바른 세션의 거부·만료 요청을 소비하는 것도 가능하다. FIX1 인계에는 수정됐다고 적혀 있지만 해당 검사 본문은 이번 diff에 없어 독립 확인은 미확인이다.

2. **T13-2 — 프록시 뒤 redirect 검사:** `request.url`이 외부 공개 origin·path를 보존할 때만 정확히 일치한다. 내부 주소로 재구성하는 프록시에서는 정상 콜백도 거부할 수 있다. 실제 프록시 구성과 요청 URL은 미확인이다. 임의의 전달 헤더를 신뢰하는 방식으로 완화해서는 안 된다.

3. **T13-3 — 실행 게이트 잠금:** 모든 자격 증명 변경이 계정 `FOR UPDATE`를 먼저 잡고 실행 측이 같은 계정의 `FOR SHARE`를 유지한다면, 계정 잠금으로 직렬화할 수 있다. 자격 증명 읽기에 별도 잠금을 추가하는 것이 필수는 아니다. 전체 쓰기 경로와 트랜잭션 격리 수준은 미확인이다.

4. **T13-4 — 해제와 승인:** 해제 시 승인을 무효화하고 `credential_state='linked'`를 유지해 모의 기본 동작으로 돌아가지 않도록 하는 선택은 타당하다. D17–D19 원문과의 정확한 일치는 미확인이다.

5. **T13-5 — 복원 비교:** 비교에서 제외하더라도 로컬 `none`을 `needs_reconnect`로 올리는 별도 규칙이 있으면 연결 이력을 잃지 않는다. 묶음의 상태로 로컬의 실제 연결을 덮어쓰지 않는 것도 타당하다.

6. **T13-6 — AAD·봉인 파서:** 식별자가 UUID이고 purpose가 제한된 enum이라면 제시된 줄 구분 형식의 모호성은 낮다. 식별자 검증, 봉인 파서, 버전 일치 검사 본문은 이번 diff에 없어 미확인이다.

7. **T13-7 — 비밀 노출 검사:** 추가 테스트는 직접 호출한 콜백의 콘솔·본문·감사 기록을 검사한다. Next 서버·프록시 접근 로그와 실제 브라우저의 Referer 동작은 미확인이다. 응답의 `no-referrer`가 서버 접근 로그의 URL 기록까지 막지는 않는다. CLI의 `Error.name`과 `code`에 민감 값이 들어가는 경우도 현재 테스트에서 빠졌다.

8. **FIX1-1 — 계정 → item 잠금:** `channel_account_id`가 불변이라는 전제에서는 먼저 읽어 계정을 잠근 뒤 item을 잠그는 순서가 설명된 변경 경로와 일치한다. 전체 잠금 그래프가 제공되지 않아 교착 상태가 없다고 확정할 수는 없다.

9. **FIX1-2 — 폐기된 갱신 결과:** 세대가 달라졌다면 이미 커밋된 연결을 보존하고 새로 발급받은 토큰을 철회하는 규칙이 타당하다. 별도로 저장 실패 시 기존 연결을 사용 불가로 표시하는 처리가 필요하다. 첫 번째 지적 사항에 해당한다.

10. **FIX1-3 — `incomplete`:** 자기 작업이 현재인 동안 `revoking`과 암호문을 유지하고 재시도로 마무리하는 방식이 타당하다. 같은 호출에서 더 새로운 토큰까지 무조건 철회해서는 안 된다.

11. **FIX1-4 — 복원 불일치:** 보고되는 단방향 `none → needs_reconnect` 변경으로 충분하다. 반드시 일반 충돌로 처리할 필요는 없다. 이번 diff에는 이름·플랫폼을 표시하는 화면 연결도 추가됐다. 브라우저 렌더링은 미확인이다.

12. **FIX1-5 — 회전 종료 코드:** 열 수 없는 행이 하나라도 있으면 exit 1이 적절하다. 일부 성공과 전체 성공을 구분할 수 있다. DB 종료 실패도 같은 원칙에 포함해야 한다.

13. **FIX2-1 — `superseded` 범위:** 제시된 정상 경로에서는 설명이 맞다. 콜백은 `revoking`을 거부하고, 재연결이 작업 ID를 지우며, 완료 전 중복 해제는 같은 작업에 합류한다. 별도 삭제·직접 수정 경로까지 포함한 보장은 미확인이다.

14. **FIX2-2 — 저장 결과 불명:** 저장됐을 수 있는 토큰을 즉시 철회하지 않는 판단은 타당하다. 다만 해시만으로는 저장되지 않은 T2를 나중에 철회할 수 없다. 자동 재조정을 보장하려면 작업 ID·처리 상태와 필요한 암호화 토큰 정보를 내구성 있게 남겨야 한다. 현재 감사 기록만으로 “롤백 후 재조회도 실패한 경우”까지 다음 check·refresh가 해결한다고 보장할 수는 없다.

15. **FIX2-3 — epoch 저장 위치:** 해제 시 자격 증명 행을 보존하고 재연결이 epoch를 초기화하지 않는 현재 경로에서는 충분하다. 계정 테이블로 이동할 필요는 없다. 앞으로 자격 증명 행만 삭제하는 경로를 추가한다면 epoch 보존 방식도 변경해야 한다. 그러한 별도 경로의 존재는 미확인이다.

16. **FIX2 추가 질문 — lease 테스트 시간 확대:** 원래 버그를 유발하는 조건과 assertion을 유지한다면 가능하다. 다만 원본 테스트가 제공되지 않아 구체적인 확대안은 판단할 수 없다. 단순히 lease 만료를 피하도록 바꾸기보다는 명시적인 실행 장벽이나 제어 가능한 시계로 순서를 고정하는 편이 낫다.
