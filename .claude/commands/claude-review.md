---
description: Claude 독립 검토자(새 컨텍스트 서브에이전트, 읽기 전용)에게 변경분 반박 검토를 맡기고 결과를 요약한다
allowed-tools: Agent, Bash(git diff:*), Bash(git status:*), Bash(git log:*), Bash(git rev-parse:*), Bash(git show:*), Read, Grep, Glob, Write
---

검토 대상: `$ARGUMENTS` (없으면 커밋되지 않은 변경분, `--base <ref>` 면 그 ref 대비 브랜치, `--commit <SHA>` 면 그 커밋 하나).

절차:
1. `git status --short`·`git rev-parse HEAD` 로 대상과 HEAD 를 고정한다. 대상 diff 의 파일 목록만 확인한다(전문을 대화에 붙이지 않는다).
2. Agent 도구로 **독립 검토자**를 띄운다(새 컨텍스트). 프롬프트에는 대상(diff 를 얻는 git 명령), 적용 규칙 파일(AGENTS.md, 해당 하위 프로젝트의 AGENTS.md·DECISIONS), 심각도 기준만 준다. **구현자의 결론·"이건 맞다"는 판단은 주지 않는다.** 검토자 규칙:
   - 읽기 전용: 파일 수정·git 상태 변경 금지. 시험은 단일 파일만, 외부 호출·실계정·비밀 금지.
   - 심각도: P0 = 불변 조건 위반·데이터 손상·보안, P1 = 실제 진입점에서 닿는 기능 오류·명세 불일치, P2 = 경계값·품질(구체적 결과가 있을 때).
   - 지적마다 파일:줄, 단계별 재현 시나리오, 수정 제안. 보고 전에 스스로 반박을 시도하고, 살아남은 것만 보고하며 기각한 후보도 짧게 적는다. 바뀐 시험 단언이 약해졌는지 반드시 본다.
   - 범위가 크면 영역별로 검토자를 나누고(동시 실행 가능 — 읽기 전용), P0·P1 은 서로 다른 관점(코드 추적·방어 장치·명세)의 검증자 3명 중 2명이 유지할 때만 확정한다.
3. 결과를 `.ai/handoff/review-<YYYYMMDD-HHMMSS>.md` 에 저장한다(커밋하지 않음).
4. 대화에는 지적 요약만 보고한다. 각 지적은 **실제 코드를 확인한 뒤** 판정한다.
   - 타당 → 무엇을 어떻게 고칠지 한 줄
   - 오탐 → 근거(파일:줄)
5. 마지막에 "반영할 항목 / 무시할 항목"을 나눠 제시하고, 사용자 승인 없이 코드를 고치지 않는다(사용자가 이미 수정까지 지시했으면 그 범위에서 진행).

검토자의 판정을 그대로 받아들이지 마라. 검증 대상은 코드이지 검토자의 의견이 아니다. 이 결과는 Claude 검토이며 다른 도구의 판정이라고 표기하지 않는다.
